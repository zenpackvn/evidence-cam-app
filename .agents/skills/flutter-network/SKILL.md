# Flutter Network

Full reference: [`template.md`](references/template.md)

## Key rules

- `DioClient` is the **only** file that imports `package:dio/dio.dart` and configures the `Dio` instance.
- `ApiClient` is generated by Retrofit (`@RestApi()`). It is the only file that defines endpoint methods.
- All interceptors are injected into `buildDio` via DI — no inline construction:
  1. **SecurityInterceptor** — SSL pinning, flavor-configurable via `AppConfig`.
  2. **RetryInterceptorFactory** — wraps `dio_smart_retry`; creates `RetryInterceptor` bound to the `Dio` instance.
  3. **LoggingInterceptor** — active in dev/uat only (`AppConfig.enableLogging`).
  4. **ErrorInterceptor** — maps `DioException` to `Failure` hierarchy.
  5. **AuthInterceptor** — added separately in DI to avoid circular dependency.
- `Failure` is a sealed class — `NetworkFailure`, `TimeoutFailure`, `UnauthorizedFailure`, `NotFoundFailure`, `ServerFailure`, `CacheFailure`, `UnknownFailure`. Never throw raw exceptions across layer boundaries — always throw `FailureException(SomeFailure())`.
- DTOs (`*_dto.dart`) live in `data/dtos/`. Always annotated with `@JsonSerializable()`. Always expose a `toEntity()` method. Never import domain entities from `data/`.
- `json_annotation` + `json_serializable` + `retrofit_generator` require `build_runner`.
- Run `dart run build_runner build --delete-conflicting-outputs` after any annotation change.

## Files

```
lib/src/core/network/
  dio_client.dart         ← Dio setup, all interceptors injected via DI
  api_client.dart         ← @RestApi() Retrofit interface
  api_client.g.dart       ← generated
  interceptors/
    security_interceptor.dart       ← SSL pinning (flavor-configurable)
    retry_interceptor_factory.dart  ← wraps dio_smart_retry
    auth_interceptor.dart
    logging_interceptor.dart
    error_interceptor.dart
lib/src/core/error/
  failure.dart            ← sealed Failure hierarchy + FailureException
```
